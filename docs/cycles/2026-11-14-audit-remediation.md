## Spec

- [x] Long Rapor starts at its first line at 320/390 px and desktop, has viewport-bounded scroll content and visible child/period/close controls, reopens at the beginning, and shares its reader with admin preview. PDF and unpublished states remain usable.
- [x] Unresolved payment returns survive reload, reopen, sibling changes and another tab in the same browser/origin. The hint is scoped to tenant, guardian, child and invoice; authoritative payment records control settlement. Failed requests cannot silently restore Pay. Partial, paid, cancelled and definitive failed/expired results reconcile correctly; blocked storage retains recoverable callback context.
- [x] DOKU-facing labels accept ordinary Unicode fee names by safe provider-boundary normalization without altering invoice snapshots, amounts or quantities. Gateway validation diagnostics retain useful error messages.
- [x] Gate explains unavailable actions before tapping while preserving legitimate lazy session generation. Teacher Home prioritizes the class/date job, distinguishes campus Gate and own attendance, and shows off-site review decisions. Unrecorded roster rows are neutral until explicitly saved. Parent Home distinguishes actual attendance, scheduled-but-unrecorded and no session, including weekend sessions.
- [x] Parent and teacher note composers show child, intended school date and audience, use a consistent latest applicable school-day default, and retain actionable error/retry feedback. Teacher row actions have meaningful accessible labels.
- [x] Admin dashboard surfaces actionable records before empty summary categories on phones. Student/invoice counts distinguish loading, empty and failure and retain previous valid counts during refresh. Single-student and group billing entry points are distinguishable; existing search context is preserved.
- [x] Regression tests cover behavioral failure cases, independent reviews clear high-confidence issues, required build/test/lint/typecheck/docs gates pass, and Chrome verification covers changed flows locally and on deployed staging.

Acceptance qualifications: failure/expiry/cross-tab race, failed-refresh and legitimate lazy session generation are supported by automated regressions; live checks cover the explicitly recorded journeys. Blocked/lost payment baseline may require manual staff verification. The weekend attendance fixture does not establish general calendar eligibility; Rapor PDF validation covers the first page, while the one-page receipt was fully inspected. No physical-device or screen-reader session is claimed.

Assumptions: browser-persisted payment hints are UX safeguards, not a cross-device ledger; no new financial authority or database schema is introduced. Calendar fixtures from the audit remain explicitly synthetic. Timing candidates require remeasurement before optimization claims. Coverage gaps are verification work, not invented product defects. Production promotion is outside this request.
