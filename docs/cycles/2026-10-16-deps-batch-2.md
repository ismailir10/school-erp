## Decisions

- Take all 11 npm bumps: `@base-ui/react` 1.9.0, `@tanstack/react-table` 9.3.1, `lucide-react` 1.55.0, `react-hook-form` 7.90.0, `react-resizable-panels` 4.14.5, `shadcn` 4.21.4, `zod` 4.6.7, `@playwright/test` 1.64.0, `@types/node` 26.6.5, `vitest` and `@vitest/coverage-v8` 5.0.4.
- The lockfile starts from dependabot's own: a fresh `npm install` hits ERESOLVE because `react` is pinned at exactly 19.3.0 while `react-dom ^19.3.0` resolves to 19.3.1, which wants react ^19.3.1. Dependabot's lockfile keeps react-dom at 19.3.0, and the jsdom 30 and framer-motion 14 bumps are re-applied on top. React itself is not moved here: that is the separate `react` dependabot group.
- `actions/checkout@v4` → `@v7` in `ci.yml` and `e2e.yml`. The other 14 checkout steps in the repo are already on v7, so this only makes them consistent.
- `@base-ui/react` 1.9 no longer replaces a Switch's explicit `aria-label` with a generated `aria-labelledby` from its field label. The guardian dialog's *Wali Utama* switch is now announced as "Tandai sebagai wali utama" (its own `aria-label`) instead of "Wali Utama". It still contains the visible label (WCAG 2.5.3 Label in Name), so the product is left alone. The test now asserts the label-in-name rule instead of the old exact string.
